- This is the Photography moment
  - Walter Benjamin, [*The Work of Art in the Age of Mechanical Reproduction*](https://en.wikipedia.org/wiki/The_Work_of_Art_in_the_Age_of_Mechanical_Reproduction) (1935)
  - Before photography, making an image required years of training. Painting was a craft, and the craft was the gate
  - Photography made the image rapidly reproducible. The 'aura' of the hand-made image collapsed
  - Art did not die. Painting was freed from the obligation to depict. Impressionism, Abstraction, Dada, Conceptual Art… Modern Art exploded *precisely because* the image became cheap
  - I actually created an artwork about this: [SoTA (State-of-the-Art)](https://www.xdlab.net/projects/sota)

- 2020s: the same thing is happening to software
  - AI made software rapidly reproducible. The craft of 'building' is no longer the gate
  - This frees artistic expression that uses software. The constraint 'you must be able to build it first' is gone
  - Making software is now easier than painting. Arguably much easier
  - Paradoxically, this is why artistic experiments with software will explode. Cheap medium → wild experimentation. Just like Photography → Modern Art
- A very important, and very interesting time
  - We are witnessing another revolution of the same scale. Enormous possibility, and at the same time many of the existing practices will vanish

**Caveat: AI is a Statistical Machine**

- AI regresses to the mean. Always
  - A model is a statistical machine. It predicts the most probable next thing
  - A [Stochastic Parrot](https://en.wikipedia.org/wiki/Stochastic_parrot) (Bender et al., 2021): it repeats patterns from its training data, convincingly, without meaning
  - Hand the whole creative process to it, and the output converges to the average: 'I have seen this somewhere', but nothing new

**Coding Agents**

- A coding agent = a model + tools. It reads your files, edits them, runs commands, reads the errors, and tries again. You describe, it builds, you review
- Agent = model + tools + a loop. The model decides the next step, a tool does it (read file, edit file, run `pnpm dev`, take a screenshot), the result goes back to the model, repeat. Every step is shown to you and can be stopped
- Its memory is the context window of the conversation. Everything it knows about your project comes from what it read this session, plus `AGENTS.md` (below)
- Permissions: it asks before running a command or touching a file outside the project. Read the command. If it makes sense, approve. "Allow all" is for later
- [Codex](https://chatgpt.com/codex) (OpenAI): <Term id="cli">CLI</Term>, VS Code extension, cloud. Included in ChatGPT plans. Runs GPT-6 Astra / GPT-6.1 Sol
- <Term id="claudeCode" /> (Anthropic): terminal, VS Code extension, desktop app, web. Needs a Claude subscription. Runs Claude Opus 5.5 / Fable 5.1
- [Cursor AI](https://cursor.com/), [GitHub Copilot](https://github.com/features/copilot), [Gemini CLI](https://github.com/google-gemini/gemini-cli): AI-integrated editors and other CLIs. Same idea, different vendors
- **We use VS Code + Claude Code**, with Claude Opus 5.5

**How to work with an agent**

- Describe what you want, specifically. Say "App Router", say which file, paste the error
- Read what it changed before you trust it: `git diff`. Throw it away with `git restore .`, keep it with `git commit`
- One task at a time. Small steps, each one checked in the browser
- `AGENTS.md` in the repo tells the agent the rules of this project. More in W1

**<Term id="harness">Harness</Term> Engineering**

- The model is the same for everyone. What makes an agent good *on your project* is everything around the model: the **harness**
- The harness is: the rules it reads first (<Term id="agentsMd" />), the guides it is pointed to (`docs/`), the memory it leaves behind (one `README.md` per experiment), the checks it must pass (`pnpm typecheck`, `pnpm build`, open the route in the browser), and the checkpoints it saves (`git commit` when something works)
- Without a harness the agent guesses: wrong folder, Tailwind you didn't ask for, Pages Router from 2023, "it works" without ever opening the page. With one, it does the same thing the same way every time
- State of the art, Oct 2026: `AGENTS.md` is the cross-vendor standard (Codex, Claude Code, Cursor, Gemini all read it; [agents.md](https://agents.md/)). Next.js writes its own block into it. On top of that: hooks (run typecheck after every edit), skills (reusable procedures), MCP (tools like the browser). The harness is now a bigger lever than the prompt
- This template ships with a harness. Read `AGENTS.md` and `docs/` once; the agent reads them every session. When it keeps making the same mistake, fix the harness, not the prompt

**Browser Tool: Claude in Chrome**

- The agent writes code; it cannot see your page unless it has a browser. With the extension (setup step 4 and 8) it opens Chrome itself: navigates to http://localhost:3000, takes screenshots, reads console errors, clicks, types, scrolls
- This closes the loop: edit → open the route → look → read the console → fix → look again. Without it the agent says "it should work". With it, it checks
- Ask like this: "Open localhost:3000/experiments/w1/time-interval, check the console for errors, and tell me what you see". Or after a change: "Open the page and confirm the circle follows the mouse"
- It runs in a visible Chrome window; you watch every click. Logged-in sites are visible to it too, so keep a separate Chrome profile for class if that bothers you
- In the VS Code chat panel, type `@browser` to hand it the browser. In the terminal, `/chrome` shows status and reconnects when it drops
- Docs: [Claude Code with Chrome](https://code.claude.com/docs/en/chrome)
